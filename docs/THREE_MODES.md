# Three separate story modes

1. **Sequential canon** (`troy-practice.yml` for one scene, existing multi-runner workflows for full stories): write, review, repair, verify memory, then commit each scene in order.
2. **Parallel scenes and reconciler** (`parallel-scenes.yml`): choose chapters, scenes per chapter and word target. Deepen scene contracts first, check proposed handoffs, draft on independent matrix runners, then reconcile actual prose and source-bound facts. Findings trigger bounded targeted rewriting and fresh reviews. Canon commits only after reconciliation converges. One scene tests transport and gates; at least two are needed to measure concurrency and cross-scene cohesion. The pilot supports at most 24 scenes. Bounded overlapping prose windows and fact trails avoid silently truncating a manuscript. Model audits remain fallible, especially for long-range semantic dependencies.
3. **Living universe / Gemini-first** (`living-universe.yml`): a beginning, cast, immutable rules and initial facts define a persistent world with no predetermined total length. Each manual run can produce one event or an explicitly bounded four-chapter episode and can resume a previous checkpoint artifact. Seeded, heavily randomized shocks are proposals for a Gemini-first director, not automatic canon. The Actions workflow uses separate runners for event planning, characters, parallel writing beats, independent review batches and targeted paragraph repairs. Gemini handles scoped writing, review and repair batches across independent projects; Qwen 7B is the local fallback. Full canonical memory is preserved; extraction, completeness and fact checks are partitioned. Source-linked summaries assist causal review while exact passages govern prose review. Editors can delete or combine owned passages, with independent model assessment before merging. Events commit only after quality and memory checks. Failed attempts preserve random draws and provisional output without changing accepted history. No schedule is installed. CPU generation can be slow on hosted runners.

Fixture runs use explicitly labeled synthetic prose. They test orchestration, not literary quality, and cannot resume into live worlds. Live failures preserve checkpoints. Tests do not establish provider availability or expert literary quality.
